# Subscription billing adjustment fixture

This deterministic fixture models a subscription billing portal as work moves
from the original feature to clarification and UAT. Primary project:
**Subscription Billing Portal** (`project-subscription-billing`). The complete
story is one subject/ticket: **BILL-101**. Clarification and UAT are source
records on that ticket, not separate adjustment tickets. The other ticket rows
in `project.json` are retained only as historical fixture data and are not part
of the Checkout checklist.

## Timeline and expected state

1. On 2025-01-08, the initial FSD creates the seven-day trial and payment-method
   requirements.
2. On 2025-01-24, a developer checks the initial implementation.
3. On 2025-01-28, clarification changes conversion to the customer's local
   seventh day and adds a grace period. The original trial requirement remains
   in history as `superseded`; it is not overwritten.
4. On 2025-02-12, UAT adds timezone display and idempotent webhook requirements
   to the same BILL-101 checklist.

The current active checklist has five items: one checked payment-method item
and four unchecked adjustment/UAT items. The superseded trial item remains
visible in history with its completion audit. `req-invoice-timezone-display` is
intentionally active without a scenario. Cancellation during grace-period
retry is an intentionally documented omitted edge case.

## Files and usage

The JSON files are canonical and support partial-ingestion and reference-failure
experiments: `project.json`, `sources.json`, `requirements.json`, `impacts.json`,
`scenarios.json`, `completion-audits.json`, `proposals.json`, and
`expected-findings.json`. Markdown documents under `documents/` are canonical
raw ingestion inputs. `fixture.json` is a convenience bundle generated by
combining those files; it is not a second source of truth.

Run `node validate.mjs` before loading. It checks JSON parsing, enum values,
foreign keys, supersession direction, and the deliberate scenario invariants.
No database or production code is required.

Start with `insight-prompts.md` for MCP questions and the AI review rubric.
Expected structured targets are in `expected-findings.json`.
